# Traps (read before Phase 3)

T1–T24 happened for real during one incident; T25–T30 are common on servers built differently. Each has: **who it applies to**, **what happens** and **the rule**. Skip the rows that do not apply to this server.

| # | Trap | Applies to | What happens | Rule |
|---|---|---|---|---|
| T1 | **Two nginx installs** (control panel + distro package) | Panels with their own web server | A bare `nginx -t` tests a config that isn't running. After a reboot the distro nginx grabbed :80, the panel's watchdog restarted the wrong one, and :443 stayed down. Deploy scripts also called the wrong binary. | Always use the full path of the **live** binary, with `-c <conf>`. Keep the distro service masked. After a reboot, check `ss -ltnp \| grep :443`. Grep deploy scripts for nginx calls. |
| T2 | **A container ignores `docker stop`** | Docker (php-fpm images) | php-fpm base images set `STOPSIGNAL SIGQUIT`; a bash PID 1 that traps only TERM ignores QUIT. Every stop waits the whole grace period (11 min). Compose kept the **new app** in "Created" meanwhile: **11 minutes of 502s in production.** | Compare StopSignal with PID 1's `SigIgn`/`SigCgt`. Set `stop_signal: SIGTERM` and trap early. Unblock a hung stop with `docker kill -s SIGTERM <c>`. |
| T3 | **`docker restart` after a DB password change crash-loops** | Laravel in Docker | The entrypoint ran `migrate` **before** `config:cache`, and the old cached config (old password) survives a restart → "Access denied" → restart loop. | After a connection-setting change, **recreate**: `up -d --force-recreate`. |
| T4 | **`config:clear` / `optimize:clear` takes the site down** | Laravel | FPM (www-data) cannot read the 600 env file and works only through the cache built by root. Clearing it → missing APP_KEY → 500 everywhere. The CLI keeps working, which hides it. | Never clear. Run `config:cache` + an FPM reload. |
| T5 | **The env file is a single-file bind mount** | Docker (bind-mounted files) | `sed -i` and editor saves create a **new inode**; the running container keeps the old file. | Write in place: python `open(p,"r+")` + `truncate()`, or `cat tmp > file`. Check the inode before and after. |
| T6 | **Redis password ordering** | Any app + Redis | App has a password, Redis has none → AUTH error. The reverse → NOAUTH. Sessions and cache die either way. | Write the value immediately before the deploy that recreates **both**. Add a pre-flight and a branch guard. |
| T7 | **`cp -p` keeps the old mtime** | Everyone | A "delete backups older than today" filter caught today's backups. | Filter by the date in the filename; always list before deleting. |
| T8 | **Docker `registry-mirrors` reload** | Docker | Removing the key and reloading keeps the old mirror. | Set `"registry-mirrors": []` explicitly. |
| T9 | **`rsync -n` without `-i`** | Everyone | Prints nothing, so a drift check "found 0 differences". | Always `rsync -anci`. Compare code folders. |
| T10 | **Docker bypasses ufw** | Docker | `ufw deny 5432` did nothing. A database sat on the internet with `changeme`. | Loopback binds + DOCKER-USER. Verify from outside, on IPv6 too. |
| T11 | **Rewritten remote history vs old local clone** | Everyone (git) | A server clone held pre-rewrite history with un-redacted keys. Pushing work based on it would re-upload them. | Base new branches on the remote's cleaned branch. Compare SHAs before pushing. |
| T12 | **Live code not in git** | Everyone | Live matched no branch (a hand-deployed feature). The next `rsync --delete` deploy would delete it while the DB already depended on it. | Drift-check before any deploy; snapshot live into a deploy branch. |
| T13 | **Panel certificate renewal failing silently** | Panels | A vhost without a `root` line made the panel's renewal crash every day; the certificate expired. | Check certificate expiry on every vhost; read the renewal job's log. |
| T14 | **curl to 127.0.0.1 without a Host header** | Most frameworks | The framework's trusted-hosts check answers 400 before routing; every smoke test looks broken. | `curl -H "Host: <domain>" http://127.0.0.1:<port>/…`, or use the public URL. |
| T15 | **`$` inside a single-quoted ssh string** | Everyone (ssh) | Variables expand on your laptop; nginx `$vars` become empty. | Send files and scripts over ssh on **stdin** (`<<'EOF'` or `< file`). |
| T16 | **UTF-8 BOM in an env file** | Everyone | `compose --env-file` refuses it; the first key is read as `﻿APP_NAME`; `grep '^APP_NAME='` misses it. | Strip with `sed -i '1s/^\xEF\xBB\xBF//'` (then remember T5). |
| T17 | **Compose project, file and label mismatch** | Docker Compose | Containers were created from paths that no longer exist; a plain `compose up` would start a duplicate stack. | Read the labels; pass `-p`, `--env-file`, `-f`; use `--dry-run` first. |
| T18 | **The healthcheck carries the old root password** | MySQL in Docker | After a MySQL root rotation the container turns unhealthy; `depends_on: service_healthy` blocks the next deploy. | Recreate the mysql service after a root rotation. |
| T19 | **Your own test shows up as an alarm** | Everyone | Proving the old password fails leaves "authentication failed" in the logs; a later agent flags it. | Note your own probes, with timestamps, in the report. |
| T20 | **False positives** | Everyone | `/lib` → `/usr/lib` made systemd units look unowned; secret scans matched `redis://localhost:6379/0` and `.env.example` placeholders. | Verify every scary hit before you report it. |
| T21 | **Livewire after an APP_KEY change** | Laravel Livewire | Open pages fail their checksum once. | Rotate at low traffic; a refresh fixes it. |
| T22 | **A subagent is blocked by the permission system** | Claude Code | The block meant "no" for now. | Report it to the user; get a fresh, explicit yes. Never do it yourself silently. |
| T23 | **`set -e` with `&&`** | Everyone (scripts) | `nginx -t && nginx -s reload` that fails at `-t` doesn't stop the script, and it prints "DONE". | Add `\|\| { echo ERROR; exit 1; }`. |
| T24 | **`rsync --delete` wipes ACME and data folders** | Everyone (rsync deploys) | `.well-known/`, `uploads/` and `logs/` were deleted on every deploy. | Exclude them explicitly. Keep empty mounted folders with `.gitkeep`. |
| T25 | **A distro PHP looks old but is patched** (or the reverse) | Ubuntu, Debian, RHEL family | Ubuntu's `8.3.6-0ubuntu0.24.04.x` is below 8.3.36 on paper but carries the fix; a script comparing numbers calls it vulnerable. Calling a vendor build "safe" because the number is high is the same mistake the other way. | For distro packages read the **package changelog** for the CVE id (`php_runtimes.sh` does). Compare numbers only for builds that follow php.net (Docker official images, Ondřej Surý, Remi, panels). |
| T26 | **`php -v` is not the PHP that serves the site** | Every PHP server | The CLI can be another version, another ini file and another package from FPM or mod_php. "Patched" and "upload_progress off" were checked on the CLI while the site ran something else. | Read the web SAPI: `php-fpm<ver> -i` + pool overrides, Apache's loaded module, the container's FPM. |
| T27 | **The panel overwrites a hand edit** | cPanel, Plesk, aaPanel, DirectAdmin, CyberPanel | A setting written into a file the panel generates disappears on the next "save" in the panel, or on its next update. | Use the panel's own place for settings (its guide says where), or a file it never touches. Re-check after the panel's next update. |
| T28 | **Several PHPs on one box** | Panels, Remi, Surý | Only the default PHP was patched; sites on the other versions stayed vulnerable. | `php_runtimes.sh` lists **every** runtime. Patch and restart each one that serves a site. |
| T29 | **Package updated, old workers still running** | Every PHP server | The package on disk is new, but the FPM master or Apache started before the update still runs the old code. | Restart (not just reload) every worker. Prove it: the master's start time is after the patch. |
| T30 | **A phpinfo test file left behind** | Every PHP server | A `phpinfo()` page used to check settings stays online and tells attackers everything. | Random name, fetch once, delete at once, prove it returns 404. Prefer `php-fpm -i` or the probe script. |
